Section 01

Git & GitHub Fundamentals

Understanding the mental model: what is happening under the hood, and how Git differs from GitHub.

Git

Local Version Control Tool

Git is a free, open-source Distributed Version Control System (DVCS) created by Linus Torvalds in 2005. It runs entirely on your local machine and tracks every modification made to code files over time.

  • Works 100% offline without internet connection
  • Stores full repository snapshot history in hidden .git folder
  • Allows lightning-fast branch creation, switching, and merging
  • Maintained via Command Line Interface (CLI) or GUI tools

GitHub

Cloud Hosting & Collaboration Hub

GitHub is a cloud platform that hosts remote Git repositories. It layers essential team collaboration features, security scanning, code reviews, automated pipelines, and cloud hosting on top of Git.

  • Hosts remote copies of your code for backup and collaboration
  • Provides Pull Requests (PRs) for peer code review
  • Automates tests & deployments with GitHub Actions
  • Hosts static websites for free via GitHub Pages

The Git 3-Tree Architecture

Unlike other backup systems that just copy files, Git manages your files across three logical areas on your machine before they ever reach a remote server like GitHub:

State 1

Working Directory

Actual files on your disk. You edit, delete, and add code here. Files can be Untracked or Modified.

Unstaged Changes
git add <file>
Stage for commit
State 2

Staging Area (Index)

The preparation dock. A preview draft of the changes you specifically selected to be bundled into the next snapshot.

Staged & Ready
git commit -m "..."
Create snapshot
State 3

Local Repository (HEAD)

The permanent database stored inside .git. Every commit is a cryptographic SHA-1/256 snapshot.

Committed History
git push origin main
Sync to cloud
Remote

GitHub (Remote)

The shared cloud repository accessible to your teammates, CI/CD runners, and hosting providers.

Cloud Synchronized
Section 02

Git Installation & Configuration

Set up Git properly on your operating system and configure your developer identity.

1
Download Git for Windows:

Download the standalone installer from the official website git-scm.com/download/win. This includes Git Bash, a complete Unix emulation shell.

2
Recommended Installer Options:

During setup, accept recommended options, specifically: default branch name set to main, and choose "Git from the command line and also from 3rd-party software".

3
Verify in PowerShell or Command Prompt:
powershell 
$ git --version
git version 2.44.0.windows.1
Option A
Install via Homebrew (Recommended):
zsh 
$ brew install git
Option B
Install via Apple Xcode Command Line Tools:
zsh 
$ xcode-select --install
Debian / Ubuntu
bash 
$ sudo apt update && sudo apt install git -y
Fedora / RHEL
bash 
$ sudo dnf install git -y

Essential First-Time Global Configuration

Git attaches your name and email to every commit you produce. This identity is permanently baked into the history. Run these commands once per machine:

1. Set Your Author Name Required

This will appear on your commits in GitHub's commit log.

bash 
$ git config --global user.name "Your Name"
2. Set Your GitHub Email Required

Must match the email address associated with your GitHub account to link commit graphs.

bash 
$ git config --global user.email "your.email@example.com"
3. Set Default Branch to 'main' Recommended

Aligns your local default branch name with modern GitHub industry standards.

bash 
$ git config --global init.defaultBranch main
4. Inspect Your Active Config Verification

Inspect all active keys and file origins (system, global, local).

bash 
$ git config --list --show-origin
Section 03

The 11 Core Git Commands

Every command you will use in daily professional engineering. Filter by name or task.

01

git init

Setup

Initializes a new, empty Git repository in the current folder or creates the metadata structure.

When you run git init, Git creates a hidden directory named .git. This folder contains all the database objects, staging index, commit trees, and configuration files. Do not delete or manually alter .git.

bash 
$ git init
Initialized empty Git repository in /path/to/my-project/.git/
Syntax / VariationDescription
git initInitializes the current working directory.
git init <project-name>Creates a new folder and initializes Git inside it.
git init -b mainInitializes the repository with main as initial branch.
Pro-Tip: Running git init in an already initialized directory is safe; it won't overwrite existing history or files.
02

git add

Staging

Moves changes from your Working Directory to the Staging Area (the Index).

Git doesn't automatically snapshot every edited file. git add lets you curate your next commit by explicitly choosing which file modifications belong together in the snapshot.

bash 
# Stage a single specific file:
$ git add index.html

# Stage ALL changes in the current repository:
$ git add .
Syntax / VariationDescription
git add <file>Stages the specific file or directory.
git add .Stages all modified, new, and deleted files in current tree.
git add -pInteractive patch mode: review and stage line-by-line chunks (hunks).
Pro-Tip: Always configure a .gitignore file before running git add . to avoid staging secrets, node_modules/, or system junk.
03

git commit

History

Permanently records the staged changes as a snapshot in the repository's history.

Every commit produces a unique cryptographic SHA hash, an author timestamp, and a commit message explaining why the change was introduced. Commits are atomic units of change.

bash 
$ git commit -m "feat: add user navigation bar"
[main a7f3b89] feat: add user navigation bar
 2 files changed, 48 insertions(+), 3 deletions(-)
Syntax / VariationDescription
git commit -m "<msg>"Creates a commit with an inline commit message.
git commit -am "<msg>"Stages all modified tracked files and commits in one step.
git commit --amendAppends new changes or modifies the message of the most recent commit.
Best Practice: Use conventional commit prefixes: feat:, fix:, docs:, refactor:, chore:. Keep first lines under 72 characters.
04

git status

Inspection

Displays the working tree status: untracked, modified, and staged files.

git status is your primary compass in Git. It informs you of your current branch, whether your branch is ahead/behind remote, and exactly which files need to be staged or committed.

bash 
$ git status
On branch main
Changes to be committed:
  (use "git restore --staged ..." to unstage)
	modified:   index.html

Untracked files:
  (use "git add ..." to include in what will be committed)
	style.css
Syntax / VariationDescription
git statusFull verbose status report with helpful tips.
git status -sShort, concise format (M=modified, ??=untracked).
git status -sbShort format including current branch tracking info.
Pro-Tip: Whenever you feel lost or uncertain before a push or rebase, run git status first!
05

git log

Inspection

Lists commit history in reverse chronological order with authors, dates, and messages.

Examine the lineage of your project. You can filter by author, date, message text, or display the branch graph visually right in your terminal.

bash 
$ git log --oneline --graph --all
* e81042c (HEAD -> main, origin/main) feat: deploy to github pages
* a7f3b89 feat: add user navigation bar
* 19280d4 fix: correct viewport meta tag
* 41d98a0 Initial commit
Syntax / VariationDescription
git logFull details (SHA, author, date, full message).
git log --onelineCondensed one-line summary for rapid reading.
git log -n 5Limits output to the 5 most recent commits.
git log --graph --allDraws an ASCII branch topology tree.
Pro-Tip: Press q to exit the paginated log view if your terminal opens in less.
06

git branch

Branching

Lists, creates, renames, or deletes branches in your repository.

A branch in Git is simply a lightweight movable pointer to a commit. Creating branches is virtually instantaneous and uses almost zero disk space, encouraging feature-driven workflows.

bash 
# List all local branches (* marks current branch):
$ git branch

# Force-rename current branch to 'main':
$ git branch -M main
Syntax / VariationDescription
git branchLists all local branches.
git branch -aLists both local and remote-tracking branches.
git branch <name>Creates a new branch without switching to it.
git branch -d <name>Safely deletes a merged branch.
git branch -D <name>Force-deletes a branch even if unmerged.
Pro-Tip: Never work directly on main in a team. Always create a descriptive branch like feature/login-form or fix/header-overflow.
07

git switch

Branching

Switches the active branch and updates the files in the working directory.

Introduced in Git 2.23, git switch was created to split the confusing, overloaded duties of the older git checkout command. switch is dedicated solely to navigating branches.

bash 
# Switch to an existing branch:
$ git switch main

# Create and immediately switch to a new branch:
$ git switch -c feature/navbar
Switched to a new branch 'feature/navbar'
Syntax / VariationDescription
git switch <branch>Switches to an existing branch.
git switch -c <branch>Creates new branch and switches to it (equivalent to older checkout -b).
git switch -Switches back to the previous branch you were on.
Modern Convention: Prefer git switch over git checkout for branch changes, and use git restore to discard uncommitted file modifications.
08

git remote

Remote

Manages connections to remote repositories like GitHub, GitLab, or Bitbucket.

A "remote" is an alias (typically named origin) pointing to the URL of the repository hosted in the cloud. It allows you to push code to or pull code from the cloud.

bash 
# Add GitHub as the 'origin' remote:
$ git remote add origin https://github.com/username/my-project.git

# Verify existing remotes and their fetch/push URLs:
$ git remote -v
origin  https://github.com/username/my-project.git (fetch)
origin  https://github.com/username/my-project.git (push)
Syntax / VariationDescription
git remote -vLists all configured remotes with their fetch & push URLs.
git remote add <name> <url>Registers a new remote repository alias.
git remote set-url <name> <url>Updates the URL for an existing remote (e.g. HTTPS to SSH).
git remote remove <name>Deletes a remote connection.
Pro-Tip: The word origin is not magic; it's just the default Git convention for your primary remote repository.
09

git push

Remote

Transfers commits from your local repository to the remote repository on GitHub.

When you push, Git uploads all commits on your current branch that do not yet exist on the remote branch, updating the remote's HEAD pointer.

bash 
# First push: set upstream tracking:
$ git push -u origin main

# Subsequent pushes on the same branch:
$ git push
Syntax / VariationDescription
git push -u origin <branch>Pushes and sets upstream link so future git push or git pull need no arguments.
git pushPushes current branch to its configured upstream tracking branch.
git push --force-with-leaseSafely overwrites remote history only if no one else has pushed in the meantime.
git push origin --delete <branch>Deletes a branch from the remote GitHub server.
Warning: Avoid git push --force on shared team branches like main, as it destroys team commits.
10

git pull

Remote

Fetches changes from the remote repository and immediately integrates them into your current branch.

Under the hood, git pull executes two commands automatically: git fetch (downloads objects from remote) followed by git merge (combines remote branch into your local branch).

bash 
$ git pull origin main
Updating a7f3b89..e81042c
Fast-forward
 style.css | 12 ++++++++++++
 1 file changed, 12 insertions(+)
Syntax / VariationDescription
git pullPulls from the tracked upstream remote branch.
git pull origin <branch>Pulls specific branch from specified remote.
git pull --rebaseReapplies your local unpushed commits on top of incoming remote commits, avoiding noisy merge commits.
Pro-Tip: Always run git pull before starting a new feature to ensure your base code is fully updated with the team.
11

git clone

Setup

Downloads an existing remote repository onto your local computer, including full history and branches.

git clone performs three actions automatically: it creates a new folder, initializes a Git repository, creates a remote named origin pointing to that URL, and checks out the default branch.

bash 
$ git clone https://github.com/facebook/react.git
Cloning into 'react'...
remote: Enumerating objects: 248231, done.
remote: Counting objects: 100% (231/231), done.
Receiving objects: 100% (248231/248231), 143.12 MiB | 18.20 MiB/s, done.
Syntax / VariationDescription
git clone <url>Clones into a folder named after the repository.
git clone <url> <folder-name>Clones into a custom named directory.
git clone --depth 1 <url>Shallow clone: downloads only the most recent commit (fast for large repos).
Pro-Tip: You don't need to run git init when you use git clone; the repository is already initialized.
Section 04

Step-by-Step: Push Local Project to GitHub

The definitive, error-free walkthrough for publishing an existing project folder to a fresh GitHub repo.

1

Create a New Empty Repository on GitHub

Log into your GitHub account and click the + button in the top right, then select New repository (or navigate to github.com/new).

⚠️
Crucial Beginner Rule: Do NOT check "Add a README file", ".gitignore", or "license" here. Leave the repository completely blank. If you add these on GitHub, your remote and local will have conflicting commit histories, causing a rejected - non-fast-forward error on your first push!
2

Open Terminal in Your Local Project Directory

Ensure your terminal (PowerShell, Command Prompt, Git Bash, or macOS Terminal) is located directly inside the root folder of your project:

bash 
$ cd /path/to/my-local-project
3

Initialize Git Repository

Turn your regular folder into an active Git tracking repository:

bash 
$ git init
4

Stage All Files and Make Initial Commit

Select every file in your project directory and commit the initial snapshot:

bash 
# Stage all project files:
$ git add .

# Record your first commit:
$ git commit -m "feat: initial project commit"
5

Rename Branch to 'main'

Older Git versions default to master. Rename it to main to match GitHub's modern default:

bash 
$ git branch -M main
6

Link Local Repository to Your GitHub Remote

Copy the HTTPS repository URL from your GitHub repository page and register it under the name origin:

bash 
$ git remote add origin https://github.com/<YOUR-USERNAME>/<YOUR-REPO-NAME>.git
7

Push to GitHub with Upstream Tracking

The -u flag links your local main branch to origin/main on GitHub for all future pushes:

bash 
$ git push -u origin main
Enumerating objects: 15, done.
Counting objects: 100% (15/15), done.
Writing objects: 100% (15/15), 18.42 KiB | 3.68 MiB/s, done.
To https://github.com/username/my-project.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
⚡ Copy All Commands in One Chain: 
git init
git add .
git commit -m "feat: initial commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
💡
GitHub Password Authentication Note: GitHub deprecated regular account password authentication over HTTPS in 2021. When prompted for password in terminal, either use a GitHub Personal Access Token (classic) with repo scope, or install the official GitHub CLI and authenticate once using gh auth login.
Section 05

GitHub Pages Deployment Guide

Host your responsive website live on the internet directly from your GitHub repository for free.

What is GitHub Pages?

A static site hosting service taking HTML, CSS, and JavaScript files directly from a repository on GitHub, optionally running them through a build process, and publishing a website.

Live URL Format: https://<username>.github.io/<repo-name>/

Essential Prerequisites

  • Your entry point must be named index.html in the repository root (or /docs).
  • Assets (CSS, JS, images) must use relative paths (e.g., ./style.css or style.css, not /style.css).
  • The repository can be Public (free on all plans) or Private (GitHub Pro/Team).
01

Ensure Project is Pushed to GitHub

Verify that your repository on GitHub contains index.html, style.css, and script.js at the top root directory.

02

Navigate to Repository Settings

On your GitHub repository page, click the Settings tab located in the top navigation bar (far right tab next to Insights).

03

Open the Pages Section

In the left sidebar menu under the "Code and automation" group, click on Pages.

04

Configure Branch & Source

Under Build and deployment > Source:

  • Leave source as Deploy from a branch
  • Under Branch, select main from the dropdown
  • Select / (root) from the folder dropdown
  • Click the blue Save button
05

Monitor Deployment & Visit Your Live Site

GitHub will automatically trigger a GitHub Actions workflow. Refresh the page after 60-90 seconds. You will see a banner displaying:

"Your site is live at https://yourname.github.io/your-project/"

Troubleshooting Common GitHub Pages Pitfalls

Issue: 404 Site Not Found

File is named Index.html or home.html instead of lowercase index.html. GitHub Pages server is Linux-based and strictly case-sensitive.

Fix: Rename file to exactly index.html, commit, and push.
Issue: CSS/JS Fails to Load (Broken Styling)

Using absolute root paths like <link href="/style.css"> causes the browser to look at username.github.io/style.css instead of username.github.io/repo/style.css.

Fix: Change links to relative paths: href="./style.css" or href="style.css".
Issue: Changes Don't Appear Immediately

GitHub Pages build workflows take between 30 and 120 seconds to complete, and browsers aggressively cache CSS files.

Fix: Hard refresh your browser using Ctrl + F5 or Cmd + Shift + R.

Section 07

Emergency Scenarios: "What Command Do I Use When...?"

Real-world scenarios every developer encounters and the immediate commands to solve them.

Use a soft reset. This moves HEAD back by one commit while leaving all modified code staged in your working directory:

bash 
$ git reset --soft HEAD~1

Restore the file back to the state of the last commit:

bash 
$ git restore <filename>

Stage the forgotten file, then amend the previous commit without changing the message:

bash 
$ git add forgotten-file.js
$ git commit --amend --no-edit

Stash your uncommitted working directory changes into Git's temporary clipboard, switch branches, and retrieve them later:

bash 
# Shelve unfinished work:
$ git stash save "WIP feature"

# Switch and do what you need:
$ git switch hotfix

# Return and restore your stashed work:
$ git switch feature
$ git stash pop
